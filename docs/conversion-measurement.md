# 데이밋 전환 계측 설정

이 기능은 2026년 11월 6일 첫 방문자 보고서에서 확인한 생성 이후 응답 전환을 측정한다. 생성자 수정·이벤트 복제·공유 화면 개편은 이 변경에 포함되지 않는다.

컬럼 하나하나의 의미·기록 주체·NULL 해석, 이벤트·JSON·외부 전송 필드 정의는 [계측 데이터 사전](measurement-data-dictionary.md)이 원본이다. 다음 AI는 운영 절차와 이 사전을 함께 읽는다. 공통 제품 측정 위에 ChatGPT Ads 전용 광고 연결을 붙인 현재 구조이며, `ads_*` 상태가 매체별로 분리된 범용 광고 전송 시스템은 아니다.

## 다음 작업의 출발점

2026-11-10 구현 기준이다. 코드와 로컬 검증이 준비됐으며 이 작업에서 프로덕션 마이그레이션·배포·운영 환경변수 설정·실제 Ads 수신은 수행하지 않았다. 기본 환경변수는 새 계측 비활성이다. 다음 세션에서는 현재 브랜치·작업 변경을 확인하고 아래 활성화 순서를 따른다. 이미 017을 적용한 환경에서는 파일을 다시 고치지 말고 후속 마이그레이션을 만든다.

**사용자가 명시한 유지 조건은 기존 Clarity 녹화·히트맵이다.** GA4·OpenAI 전환 계측의 허용·거부·비활성화를 Clarity에 적용하지 않는다. 이 결정을 경로 보호나 성능 개선을 이유로 뒤집지 않는다. Clarity의 실제 페이지 경로 수집과 광고 SDK의 경로 격리는 아래처럼 별도로 다룬다.

## 이제 답할 수 있는 질문

데이터 수집 기반이며 분석 대시보드가 자동으로 생긴 것은 아니다. DB는 읽기 전용 SQL로, 브라우저 퍼널은 GA4 탐색으로, 광고 귀속은 Ads Manager로 확인한다.

| 질문·지표 | 데이터와 분모 | 해석 범위 |
|---|---|---|
| 만든 일정 중 실제 응답이 한 번이라도 저장된 비율 | 신규 생성 이벤트 전체와 `first_submitted_at` / 최초 제출 로그 | 참여자 이름만 등록한 빈 행을 제출로 잘못 세지 않음. 빈 값의 명시적 저장은 제출 |
| 생성 → 첫 제출, 응답 슬롯 2개 활성화까지 걸린 시간과 1일·7일 전환율 | 생성·최초 제출·`group_activated` 시각 | 해당 관찰 기간을 채운 생성 코호트로 계산. 현재 참여자 삭제에 흔들리지 않는 과거 퍼널은 DB 로그 사용 |
| 날짜만/시간 포함, 가능/불가능 모드의 응답·활성화 차이 | 전체 DB 생성 속성과 확정 결과 | 상관관계. 사용자가 모드를 직접 고르므로 원인·개선 효과로 단정하지 않음 |
| 어디서 생성 폼·이벤트에 들어와 편집·저장으로 이어지는지 | 허용한 브라우저의 폼 진입·열람·편집 + 서버 확정 전환 영수증 | 동의·차단·전송 유실 영향을 받음. 전체 방문자 퍼널과 다름 |
| 링크 복사·복사 실패·저장 요청 실패가 어디서 생기는지 | 허용한 브라우저 행동 로그와 Clarity 이벤트 표시 | 복사는 실제 공유·상대방 열람이 아님. 저장 요청 실패에는 서버 저장 후 응답 유실도 포함 |
| 유입 소스·캠페인·인앱 여부별 전환과 제목 수정 여부의 차이 | 허용한 브라우저의 정제된 속성 | 원문 제목·접근 키를 외부에 보내지 않음. 유입 문맥은 30일 보관하며 별도의 최초/최종 접점 모델은 없음 |
| 재방문·다른 날 재생성·응답자가 나중에 생성자가 되는 경로 | 유지되는 방문 ID와 허용 후 행동·전환의 연결 | 같은 브라우저 기준 근사. 실제 첫 방문·계정·동일인·교차 기기를 확정하지 못함 |
| ChatGPT Ads가 어떤 전환을 가져왔는지 | Pixel+CAPI의 같은 UUID와 Ads Manager 귀속 결과 | 기본 최적화 전환은 `event_created`. 실제 적격 광고 접점·수신 확인 전에는 광고 성과로 보고하지 않음 |
| 어떤 조작에서 막혔는지 | 기존 Clarity 녹화·히트맵 | 새 계측 허용 후 이벤트 마커로 녹화 탐색 가능. 녹화 자체는 새 허용·거부와 독립 유지 |

현재 알 수 없는 것은 **실제 공유 완료, 실제 사람 수, 최종 일정 확정, 가입 퍼널, 교차 기기 리텐션, UI 변경의 인과 효과**다. `availability_updated`는 재저장이며 실제 내용 변경을 보장하지 않는다. 철회 시 방문 연결을 지우므로 과거 브라우저 코호트 수치도 달라질 수 있다. 프로필 생성 시각·마지막 활동 시각을 첫 방문과 서비스 이탈로 바꾸어 해석하지 않는다. 과거 데이터에 새 제출 시각을 소급 채우지 않는다.

## 성능 경로와 검증 범위

| 경로 | 현재 처리 | 남는 비용·제약 |
|---|---|---|
| 화면·그리드 조작 | 셀 선택·드래그·hover마다 새 계측을 보내지 않음. 정해진 진입·편집 시작·복사·저장 단위만 기록 | 기존 Clarity 녹화 비용은 유지. GA4·OpenAI SDK 실행 비용이 0인 것은 아님 |
| 브라우저 SDK | 허용 후 비동기 로드. `/measurement`는 React·CSS·Header·로그인·AdSense 없이 정적으로 제공하고 인증 갱신 프록시도 제외 | 광고 SDK 자체의 다운로드·실행과 iframe 한 개. `NEXT_PUBLIC_*` 변경 시 재빌드 필요 |
| 일반 API 조회·인증·삭제 | 측정 문맥 헤더와 그에 따른 저장소 접근 없음 | 생성 POST·응답 저장 PATCH에서만 문맥 첨부. 행동 전용 요청은 별도 전송 |
| 생성·응답 저장 | DB 확정 후 영수증 연결의 두 읽기를 병렬화, 이후 원자적 확보. 세 DB 호출의 공유 abort budget은 1초 | 일반 성공 시 추가 HTTP 호출 3회·대기 2단계. 제한시간 도달 시 사업 데이터 성공을 유지하고 영수증을 생략하므로 외부 전환 일부 누락 가능. DB 트리거와 기존 사업 DB 요청 시간은 이 1초에 포함되지 않음 |
| DB 기록 | 생성·저장 트랜잭션에 로그 삽입. 부모 이벤트 잠금은 최초 제출에만 사용 | 최초 제출이 같은 그룹에 몰리면 직렬화. 재저장에도 로그 1개 삽입·인덱스 유지 비용은 있음 |
| 광고 재전송 | 응답 이후 `after`. 최대 10건의 동의 조회·CAPI 전송을 묶고 상태 갱신은 병렬. 같은 인스턴스의 동시 flush는 Promise 공유 | 최대 10건 기준 DB 최대 12회·CAPI 1회. DB 공통 abort 10초, 외부 요청 timeout 5초. 서로 다른 인스턴스의 중복 작업은 여전히 가능하며 동일 전환 ID로 광고 중복 집계를 방어 |
| 전송 대기 조회 | 미전송·동의·방문 ID가 있는 전환 3종만 부분 인덱스에 포함 | 전체 행동 로그의 보유 기간·삭제 작업과 분산 전송 lease는 아직 미구현 |

로컬 production 빌드 산출물에서 숨김 문서 HTML은 **35,306 → 2,288바이트**, Next.js 외부 스크립트 참조는 **17 → 0개**로 줄었다(예시 Pixel 활성 설정, 압축 전 HTML). SDK 본체 바이트·캐시·실사용자 LCP/INP 수치는 포함하지 않는다. 로컬 PGlite에서 017과 SQL 검증을 실행하고 행동 20,000건·대기 전환 20건 fixture의 대기 조회가 부분 인덱스를 사용하는 것을 확인했다. 이는 프로덕션 부하 시험이 아니다.

운영 활성화 전후에는 같은 조건에서 생성·저장 API의 p50/p95, LCP/INP, DB 잠금 대기, 전송 대기 건수·나이·실패·중복 시도를 확인한다. 전체 계측 지연이 0이거나 성능 문제가 없다고 단정하지 않는다. 대표 데이터의 `EXPLAIN (ANALYZE, BUFFERS)`와 동시 최초 제출 부하는 별도 검증 항목이다. 앱 또는 분석 화면을 추가하는 방식으로 픽셀 문서를 무겁게 만들지 않는다.

## 활성화 순서

2026-11-11 운영 DB dry-run에서 미적용 대상은 `017_conversion_measurement.sql` 1개였다. 현재 `check-migrations` 필수 검사는 DB에 적용되지 않은 마이그레이션이 있으면 PR 병합을 막으므로 사람이 적용한 뒤 검사를 다시 실행해야 한다. 에이전트의 커밋·푸시·병합 권한은 프로덕션 DB 적용 권한을 대신하지 않는다.

현재 `supabase/config.toml`은 `[inbucket]` 형식을 사용하며 CLI 3.1.0에서는 설정 로드가 실패한다. 설정 변경을 이 기능과 섞지 않고 호환 버전으로 확인한다: dry-run은 `npx --yes supabase@2.75.0 db push --dry-run`, 실제 적용은 사람이 같은 버전의 `db push`를 실행한다. 이후 CLI·설정 업그레이드는 별도 작업이다.

1. `017_conversion_measurement.sql`을 검토하고 사람이 프로젝트의 마이그레이션 절차로 적용한다. 에이전트는 프로덕션 DB에 적용하지 않는다. 기존 참여자의 과거 제출 시각은 추정하지 않고 NULL로 남긴다.
2. GA4 관리자에서 해당 웹 데이터 스트림의 **향상된 측정을 모두 끈다**. 페이지 조회 고급 설정의 브라우저 기록 이벤트에 따른 페이지 변경도 비활성인지 확인한다. 새 모드가 정제한 경로로 수동 페이지뷰를 보내므로 자동 기록은 중복과 원본 접근 경로 수집을 유발할 수 있다. 양식 자동 측정의 form_destination도 현재 접근 경로를 포함할 수 있으므로 양식·검색·외부 링크를 포함해 자동 수집을 켜지 않는다. 데이터 스트림에서 인증용 쿼리 매개변수의 데이터 삭제 설정도 점검한다.
3. Ads Manager의 전환 설정에서 Pixel ID와 **Conversions API 전용 키**를 발급한다. 일반 OpenAI 모델 API 키를 사용하지 않는다. 계정·캠페인·과금은 이 코드가 변경하지 않는다.
4. 아래 환경변수를 Vercel Production에 설정하고 재배포한다. `NEXT_PUBLIC_*`는 빌드 시 브라우저 번들에 포함되므로 재배포가 필요하다. 실제 키는 저장소·문서·클라이언트 코드에 넣지 않는다.
5. 실제 도메인에서 측정 허용 후 테스트 이벤트를 생성한다. DB 기록, 브라우저 Pixel 요청, 서버 전송 상태와 Ads Manager 수신 이벤트를 각각 확인한다. 실제 광고 귀속은 별도의 적격 광고 접점이 필요하며 코드 검증만으로 입증되지 않는다.

## 환경변수

| 이름 | 구분 | 값과 역할 |
|---|---|---|
| `MEASUREMENT_ENABLED` | 서버 | `true`일 때 계측 API와 CAPI 전송 활성화 |
| `NEXT_PUBLIC_MEASUREMENT_ENABLED` | 공개 | `true`일 때 동의 기반 GA4·OpenAI 전환 계측. `false`는 이 두 계측을 비활성화. Clarity 녹화는 별도 프로젝트 ID로 기존 동작 유지 |
| `NEXT_PUBLIC_SITE_URL` | 공개 | 실제 운영 origin. 브라우저 origin이 다르면 디버그 모드 외에는 계측 비활성화 |
| `NEXT_PUBLIC_GA_MEASUREMENT_ID` | 공개 | 기존 GA4 측정 ID |
| `NEXT_PUBLIC_CLARITY_PROJECT_ID` | 공개 | 기존 Clarity 녹화·히트맵 프로젝트 ID. 전환 계측 스위치와 별도로 동작하며 비워둘 때만 비활성화 |
| `NEXT_PUBLIC_CHATGPT_ADS_PIXEL_ID` | 공개 | Ads Manager에서 받은 Pixel ID. 서버와 브라우저가 동일 ID 사용 |
| `CHATGPT_ADS_API_KEY` | 비밀 | CAPI 전용 키. 서버 Authorization 헤더에만 사용 |
| `NEXT_PUBLIC_CHATGPT_ADS_CONVERSION_EVENTS` | 공개 | 기본 `event_created`. 허용 목록은 `event_created,availability_first_submitted,group_activated` |
| `CHATGPT_ADS_VALIDATE_ONLY` | 서버 | `true`이면 CAPI 요청은 검증만 수행하고 전송 완료로 표시하지 않음. 브라우저 Pixel의 테스트 모드는 아님 |
| `NEXT_PUBLIC_MEASUREMENT_DEBUG` | 공개 | 기본 `false`. 개발·미리보기에서 테스트할 때만 `true`. 실제 광고 이벤트가 발생할 수 있으므로 테스트 Pixel 사용 |
| `CRON_SECRET` | 비밀 | 재전송 작업 인증. 비워두면 외부에서 flush 호출 불가 |

기본 파일은 새 전환 계측을 비활성화한다. ID나 키가 없으면 해당 광고 전송은 실행하지 않는다. 서버 키는 `NEXT_PUBLIC_`로 만들지 않는다. Clarity는 기존 프로젝트 ID로 실제 화면 녹화와 히트맵을 유지하고, 전환 측정 스위치나 GA4·OpenAI 전환 측정 선택으로 녹화 설정을 바꾸지 않는다. 광고용 숨김 iframe은 별도의 사용자 녹화로 수집하지 않는다.

Clarity는 실제 페이지를 녹화하므로 페이지 경로도 수집한다. DOM 마스킹은 URL을 숨기는 기능이 아니다. 이벤트 화면과 호버 팝업의 기존 마스킹은 유지하며, 이벤트 이름만 전달하는 Clarity 태그로 동의 후의 전환 동작을 녹화에서 찾을 수 있다. OpenAI 픽셀에 대한 접근 경로 격리는 계속 별도 iframe에서 처리한다.

## 이벤트와 확정 결과

전체 이벤트의 발행 조건·기록 주체·내부/GA4/Clarity/ChatGPT Ads 수신처와 해석 제한은 [데이터 사전의 이벤트 정의](measurement-data-dictionary.md#3-이벤트-정의와-수신처)를 따른다. 이벤트 이름만으로 구매·공유 완료·실제 사람 수를 추정하지 않는다.

DB 트리거가 최초·마지막 제출 시각과 전환을 같은 트랜잭션에 기록한다. 이벤트 행 잠금과 고유 키로 첫 제출·활성화 중복을 막는다. 빈 availability를 저장하는 것도 유효한 제출이다. 실제 일정 조율 데이터의 운영 집계는 브라우저 측정 동의와 별도로 남는다.

새 전환 계측의 브라우저 행동·방문 식별·유입·GA4·OpenAI 전송은 허용한 경우에만 처리한다. 동의한 브라우저를 계정이나 실제 개인과 동일시하지 않는다. 이 식별자를 이벤트 수정 권한으로 사용하지 않는다. 허용 이전 행동은 소급 복구하지 않는다. 기존 Clarity 녹화는 이 전환 측정 선택과 별도로 운영한다.

## ChatGPT Ads 연결

각 전환은 `custom` 타입과 정확한 `custom_event_name`으로 전송한다. 데이밋의 그룹 생성은 예약 확정이나 구매가 아니다. 처음에는 **event_created 하나**를 광고 최적화 대상으로 설정한다. 이름만 같은 표준 전환을 고르지 말고 Ads Manager에서도 Custom과 정확한 이름을 선택한다.

브라우저 `event_id`와 CAPI `id`는 DB 영수증의 동일 UUID다. SDK의 현재 경로 자동 수집으로 접근 키가 노출되지 않도록 픽셀은 동일 출처의 숨겨진 `/measurement` 문서에서 실행한다. iframe의 referrer는 보내지 않으며, 메시지는 부모·정확한 출처·허용 전환 형식을 검증한다. 초기화 전후 동의 철회 시 대기 이벤트도 폐기한다.

원본 `oppref`와 Pixel이 생성한 `__obref`는 사용 가능한 경우에만 전달한다. 이름·이메일·제목·비밀번호·응답 시간표는 전송하지 않는다. 외부 전환의 금액을 임의로 만들지 않는다.

`group_activated`는 두 번째 응답자의 브라우저에서 발행하지 않는다. 생성 이벤트에 보관한 생성자의 광고 문맥으로 **CAPI에서만** 전송한다. 이 전환이 기본 GA4에 자동 등록되는 것은 아니다. 그룹 지표의 기준은 내부 DB다.

## 재전송과 운영

생성·저장·행동 요청이 끝난 뒤 Next.js `after`에서 대기 전환을 최대 10건씩 묶어 처리한다. 같은 인스턴스의 동시 실행은 합치지만 분산 lease는 없으므로 다른 인스턴스 간 중복 시도는 남는다. 실행 중 새로 들어온 전환이나 10건을 넘은 대기 전환은 다음 요청·스케줄러까지 남을 수 있다. 전송 오류는 일정 저장 성공을 실패로 바꾸지 않는다. 실패한 전환은 ID·시각을 유지하고 지수 백오프하며, 최초 시각을 새로 꾸며 보내지 않는다. API 허용 기간보다 짧은 최근 6일을 처리한다.

[공식 CAPI 규격](https://developers.openai.com/ads/conversions-api)은 한 이벤트 검증 실패 시 묶음 전체가 실패한다고 명시한다. 선택적 광고 참조가 빈 문자열·공백 또는 길이 제한 위반이면 전송 객체에서 생략하고, 유효한 불투명 참조는 원문 그대로 전달한다. 검증 오류는 수신 상태와 함께 확인하며 잘못된 이벤트를 완료 처리하지 않는다.

트래픽이 없는 시간에도 재시도하려면 운영 스케줄러에서 `GET /api/measurement/flush`를 호출하고 `Authorization: Bearer <CRON_SECRET>`을 전달한다. 자동 cron 등록은 이 변경에 포함하지 않는다. 별도 스케줄러가 없으면 다음 측정 요청 때 처리된다. 동의 철회한 방문자의 대기 전송은 제외한다.

기본 이벤트와 광고 귀속 전환은 분모가 다르다. 내부 DB는 저장 결과 전체를 기록하지만 외부 전송은 허용한 방문자·브라우저 차단·광고 귀속 조건에 따라 적다. Ads Manager 수치와 DB 총량의 완전한 일치를 목표로 삼지 않는다.

계측 테이블에는 RLS를 적용하고 anon·authenticated 권한을 주지 않는다. Realtime publication에도 추가하지 않는다. 방문·광고 문맥의 보유 기간과 정기 삭제 작업은 운영 정책에 맞춰 별도로 설정한다.

## 확인 절차

- 미설정·명시적 비활성·개발 기본값: 새 광고 전환 요청 없음. Clarity 프로젝트 ID가 설정돼 있으면 기존 녹화 유지.
- 허용 이전·거부·철회: 새 전환 계측 행동과 GA4·OpenAI 전환 없음. 철회 시 Google 측정 중지 플래그와 Pixel consent=false 적용. Clarity 녹화 설정에는 적용하지 않음.
- 참여자 등록·취소: first_submitted_at은 NULL.
- 빈 응답 저장: first_submitted_at과 첫 제출 전환이 한 번 기록됨.
- 재저장·응답 유실 재시도: 같은 첫 제출·생성 ID를 재사용하고 활성화도 한 번만 기록됨.
- CAPI 오류·키 없음: 일정 생성·저장 성공은 유지되고 전송 대기 기록은 남음.
- Pixel 네트워크 요청: source_url과 referrer에 실제 `/e/{접근키}`가 없어야 함.
- `npm run verify`. DB 로컬 검증은 017 적용 후 `supabase/tests/conversion_measurement.sql`을 실행하며 테스트 데이터는 롤백된다.

새 지표는 마이그레이션 이후 생성·저장 기록부터 분석한다. 7일 전환율은 7일이 지난 생성 코호트로, 30일 재생성은 30일 관찰 가능한 브라우저로 계산한다. 작성자 본인 응답과 식별 불가 응답을 별도 구분하고, 테스트·주차별 시리즈는 목적에 따라 분리한다.
